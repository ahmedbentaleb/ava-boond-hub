Les écrans qui n'existent pas encore chez Ava

  • Contrat RH, avenant, profil type
  • Achat, produit, groupement
  • Tout l'emailing
  • Les modèles d'action

Les écarts qui reviennent partout

  • La création se fait dans une fenêtre, alors que Boond ouvre une page qui devient la fiche
  • Pas de pied de fiche « Référence : … Créé le … par … »
  • Des compteurs sur les onglets, alors que Boond n'en a aucun
  • L'édition passe par une fenêtre, au lieu de l'édition directe
  • Les messages quand une liste est vide ne sont pas les mêmes
  • Le nom, dans une liste, n'est pas cliquable

Ce qui a été tranché en regardant l'écran de Boond

  • Deux contrats qui se chevauchent : Boond les enregistre avec une alerte, Ava les refuse
  • Créer un projet crée aussi un besoin, un positionnement et une prestation
  • Le contact exige un nom et un prénom ; le candidat, un nom et un prénom ; la ressource, un nom, un prénom et un e-mail

Un défaut de Boond, non reproduit

Un décalage de 2 heures entre l'heure de la carte et celle du formulaire d'action. Ava doit afficher l'heure de Casablanca partout (la date par défaut de la démo suit encore Paris : écart AC-011).

Ce qui n'a pas été relevé

  • La fiche d'une facture fournisseur (il faut déposer un fichier, c'est à Hamada de le faire)
  • La loupe de doublon (risque de données réelles)
  • Quelques fiches remplies restent en attente de l'autorisation d'Hamada
  • Ce qu'un envoi de mail crée ensuite
  • Environ 36 points « à vérifier » côté Boond

L'ordre de correction recommandé

  1. Le transversal d'abord, parce qu'il touche presque toutes les fiches : le pied de fiche, la création en page qui devient la fiche, l'édition directe, les messages vides, le retrait des compteurs sur les onglets.
  2. Les objets existants, un par un, du plus utilisé au moins utilisé : candidat, ressource, besoin, société, contact, positionnement, projet, prestation.
  3. Les écrans absents : contrat RH, achat, produit, profil type, groupement.
  4. Le « cliquable » (23 écarts, rapide à corriger), puis les actions.
  5. Le simulateur de mails (rien n'est transmis), puis l'envoi réel plus tard.

Ce que Hamada doit faire

Lire ce rapport et le valider. Alors seulement, Code commence. Dans Boond, les objets de test créés pendant le relevé sont à supprimer par Hamada ; aucun mail n'a été envoyé, aucun objet réel n'a été modifié.
