## Les niveaux, et qui autorise quoi

| Niveau | Qui | Il autorise |
|---|---|---|
| 1 · Les règles | BRAIN | le juge à écrire les tests |
| 2 · Les tests | le juge (Brain Code), **avant** le code | les codeurs à coder ; ⛔ un codeur ne touche jamais un test (D-78) |
| 3 · Le code | Grok (lots 1, 2) · Code Lot 3 (lots 3, 2c) | rien : il livre |
| 4 · Les contrôles automatiques | le **cliquet** (un script, pas une IA) · le **sabotage** · la **démo** | ⭐ ensemble, la phrase « prêt » — **rien d'autre ne l'écrit** (D-83, D-116) |
| 5 · L'autorisation d'audit | BRAIN | l'audit, seulement sur « prêt » |
| 6 · L'audit indépendant | une autre session, copie neuve | **accepté** → les lots suivants ; **refusé** → retour au niveau 1 |

## ⭐ D-116 (05/10) — le sabotage et la démo autorisent, avec le cliquet

| Règle | Tranché |
|---|---|
| **Sabotage** | une case du cliquet casse le code exprès, test par test (une mutation par règle jugée), et exige que **chaque** test devienne rouge. Un test resté vert = **aveugle** = KO. Le juge écrit les mutations ; elles sont des fichiers du juge |
| **Démo** | une case du cliquet joue `make.sh demo` (taille démo) et sa porte, puis mesure les listes : 95e centile **sous 150 ms**. KO sinon |
| **« prêt »** | la dernière ligne du cliquet, écrite seulement si cliquet, sabotage **et** démo sont verts |

## ⭐ D-117 (05/10) — le 12e audit couvre ce qui a avancé sans lui

Les lots 3 et 2c ont démarré avant que l'audit du lot 2 soit accepté (Hamada, 05/10 : ne pas attendre). Le 12e audit
juge donc **les lots 2, 3 et 2c ensemble**, sur la fusion des trois branches. Aucun lot suivant (5.8) ne part avant
son acceptation.
