1. LE PROJET EN CINQ LIGNES
───────────────────────────
Ava Manager remplace Boond Manager pour une ESN (gestion des candidats,
ressources, besoins clients, positionnements, prestations, temps).
Une société = une base. Le principe qui commande tout :

  ⭐ TOUT DOIT ÊTRE PARAMÉTRABLE.

  POLITIQUE    toute bifurcation métier     table « politique », lue en base
  MUR          tout invariant               15 murs M-1..M-15, DANS la base
  RÉFÉRENTIEL  toute liste de valeurs       tables « ref_* »

Un « if » métier écrit en dur dans le code est un REFUS D'AUDIT.

Pile : PostgreSQL 16 · Node 22 + TypeScript + Fastify + « pg » (pas d'ORM)
       · React 19 + Vite · node:test + Playwright.

5. LA MUTATION — LE CŒUR DE TON TRAVAIL
───────────────────────────────────────
Un test qui reste vert quand le code est faux est un test AVEUGLE.
On a déjà eu une assertion verte pendant qu'un mur était percé.

Protocole, UN sabotage à la fois, DANS TON CLONE SEULEMENT :
  1. arbre propre : « git status » vide
  2. tu appliques UN sabotage
  3. tu relances les portes concernées (et les assertions si c'est la base)
  4. tu notes : combien de portes sont restées VERTES
  5. « git checkout -- . » et, si c'est la base, tu la refais (§2.2)
  6. « git status » vide avant le sabotage suivant

Les sabotages minimum — ajoute les tiens :

  S1  toutes les commandes refusent INTROUVABLE, sans rien écrire
  S2  les commandes écrivent, mais n'écrivent plus l'événement
  S3  une commande écrit, puis lève : la transaction est-elle annulée ?
  S4  on retire la vérification de DROIT d'une commande (fais-en 5)
  S5  on remplace la lecture d'une politique par sa valeur par défaut
      écrite en dur (fais-en 5, dont « candidat.note.echelle »)
  S6  dans « ava_audit », on désactive un trigger de mur :
        ALTER TABLE ... DISABLE TRIGGER ...   (fais-en 3, murs différents)
  S7  on rend le DELETE à « ava_app » (GRANT DELETE) — M-8
  S8  on change un libellé dans /web — une porte doit tomber
  S9  on change une couleur du thème dans /web — une porte D doit tomber,
      en clair ET en sombre
  S10 on fait calculer au front une valeur que le serveur devrait
      donner — quelque chose doit le voir

Résultat attendu dans « rapport/MUTATIONS.md » :
  | Sabotage | Portes lancées | Tombées | RESTÉES VERTES | Verdict |
Chaque porte restée verte sous un sabotage qui la concerne est un
constat. ⭐ Le chiffre à rendre : « sur N sabotages, X portes aveugles ».


6. LE FORMAT D'UN CONSTAT
─────────────────────────
Numéros « V-001 », « V-002 »... (le CODE numérote en B-, le BRAIN en A- :
ne les mélange jamais). Un numéro ne se réattribue jamais.

  ### V-001 — <le défaut, en une phrase>
  Cible        CODE · BRAIN · les deux
  Famille      A..J · contrôle n° de la grille s'il y en a un
  Gravité      critique · elevee · moyenne · bonne
  Preuve       fichier:ligne, ou commande + sortie exacte
  Reproduire   la commande qui le montre, copiable
  Prétend      ce que le contrôle, le test ou la spec DIT vérifier
  Mesure       ce qu'il vérifie RÉELLEMENT
  Correction   une phrase, sans code

Échelle de gravité, et pas une autre :
  critique   un mur percé, une donnée fausse servie, une porte aveugle
             sur un point bloquant, une faille exploitable
  elevee     une règle du projet violée (if en dur, front patché, ...)
  moyenne    un écart au contrat sans effet immédiat
  bonne      ce qui est bien fait et doit le rester — oui, tu le notes
