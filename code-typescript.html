Pourquoi TypeScript

Mis à jour le vendredi 16/10/2026 à 07h16 (heure de Casablanca) · relevé dans le code de la version en ligne et dans le journal

Tout le code d'Ava Manager — serveur, écrans, tests — est écrit en TypeScript, en mode strict. C'est JavaScript, avec un correcteur qui relit chaque ligne avant qu'elle ne parte en ligne et refuse celles qui ne tiennent pas ensemble.

1seul langage du haut en bas : serveur, écrans, tests
94actions déclarées chacune une fois (mesure du 11/10)
588contrôles numérotés P-xxx dans les tests
~42 000lignes de serveur et d'écrans, dont 53 contournements du correcteur

Ce que le correcteur nous apporte, avec des exemples réels

Ce qu'il faitExemple dans ce code
Une action ne peut pas être mal déclaréeChaque action est une seule entrée dans la déclaration : sa nature, ses champs, ses droits. Une faute de nature, de rôle ou de type de champ ne compile pas.
Une règle est tenue par la machine, pas par une relectureLe code d'une action ne peut pas lire une valeur brute envoyée par l'extérieur : cette entrée n'existe plus dans son type. Une relecture humaine peut l'oublier ; le compilateur, non.
Il a trouvé une vraie erreur dans la version en ligneLe 14/10, une vérification a signalé une erreur de type dans le calcul des projets, présente dans le code en ligne. Elle a été classée défaut du code (D-189) et corrigée dans le Livrable 1.
Un langage pour tousLes écrans, le serveur et les tests parlent la même langue. Un changement qui traverse les trois se fait sans traduire.

Ce qui n'est pas encore vrai

On le dit pour que personne ne croie le contraire.

ConstatCe que ça veut dire
Pas de types partagés entre le serveur et les écransLes écrans redéclarent à la main les formes que le serveur envoie. Ce qui est commun, c'est le langage, pas les fichiers. Une évolution du serveur peut donc casser un écran sans que le correcteur le voie.
Le correcteur n'est pas encore une porte automatiqueOn ne le lance pas dans la chaîne de contrôles : Tests le lance à la main. La construction des écrans, elle, ne vérifie pas les types. À brancher.
Le « strict » n'est pas absolu53 endroits contournent le correcteur sur environ 42 000 lignes.
Le texte du choix est en retardLe texte de décision parle de « pages rendues par le serveur » ; l'écran est devenu une application React. Il n'existe pas de texte d'architecture dédié au choix du langage.

Ce qu'on ne fera pas, et pourquoi c'est une décision

On n'écrit pas la base en TypeScript. Les droits, les contraintes et les migrations restent en SQL : c'est la base qui refuse, même si le code se trompe. Le correcteur protège le code ; le SQL protège les données.

Le correcteur ne remplace pas les contrôles de Tests. Il attrape les fautes de forme. Seuls les contrôles numérotés P-xxx prouvent qu'une règle du métier tient : c'est pourquoi les deux existent.
